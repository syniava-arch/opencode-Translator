# Prūsisks wirdeīns — прусский словарь и переводчик

Словарь-переводчик прусского языка (Prūsiska bilā) с полным набором
словарных статей, переводов на шесть языков и словоформ (склонение и
спряжение).

```
10 864 словарные статьи
10 539 уникальных лемм
83 555 переводов (ru, en, de, lt, lv, pl)
303 834 записи о словоформах
150 300 уникальных словоформ
```

## Быстрый старт

```bash
cd prussian
python3 server.py
# → http://127.0.0.1:8765
```

Нужен только Python 3.11+ (стандартная библиотека, без зависимостей).

Или из командной строки:

```bash
python3 translate.py kalba
python3 translate.py --lang en Dēiws
python3 translate.py --from ru спорить
python3 translate.py --json --from ru дом | head
```

## Что умеет

**Словарь.** Поиск по прусскому слову в любой форме и по переводу на выбранный
язык. Диакритика необязательна: `deiws` найдёт `Dēiws`, `kalbei` — `kalbēi`.
Для каждой статьи показаны:

- лемма, часть речи, род, номер парадигмы;
- переводы на русский, английский, немецкий, литовский, латышский и польский;
- этимологическая помета/источник (`desc`);
- полная таблица склонения или спряжения.

**Разбор словоформ.** Любая форма находится в индексе и отдаёт лемму,
грамматический тег и перевод:

- существительные — 8 форм (nom/gen/dat/acc × sg/pl);
- прилагательные и числительные — 75 форм (3 рода × 2 числа × 4 падежа,
  сравнительная и превосходная степени, наречие);
- глаголы — 90 форм: настоящее, прошедшее, сослагательное (6 лиц),
  повелительное, оптатив, три причастия (действительное наст./прош.,
  страдательное прош.) по родам, числам и падежам;
- аналитические перфект и футурум собираются в интерфейсе по той же схеме,
  что и на оригинальном сайте.

**Перевод текста.** Вкладка «Перевод текста» разбирает фразу по словам:
каждое слово приводится к словарной форме и переводится отдельно
(прусский → русский/английский/… и обратно). Это словарный разбор, а не
машинный перевод предложений.

## Данные

| Файл | Что внутри |
|---|---|
| `data/full.nvh` | исходный снимок зеркала (10 861 статья, 6 языков, все формы) |
| `data/entries.jsonl` | 10 861 статья: лемма, POS, род, парадигма, 6 переводов, все формы с тегами, помета |
| `data/extra_entries.jsonl` | статьи, добавленные вручную (нет в зеркале); подмешиваются при сборке |
| `data/words.csv` | таблица «слово — переводы» (разделитель `;`) |
| `data/forms.csv` | таблица «статья — словоформа — тег» (303 743 строки) |
| `data/wordlist.json` | 10 523 леммы, как в исходном зеркале |
| `data/dictionary.sqlite` | те же данные с индексами для запросов |

Схема SQLite:

- `entries(id, headword, head_norm, pos, gender, paradigm, desc, derived_from)`
- `translations(entry_id, lang, sense, text, text_norm)`
- `forms(entry_id, form, form_norm, tag)`

Теги словоформ: `sg.nom`, `pl.gen`, `prs.sg1`, `prt.pl2`, `subj.sp3`,
`imprt.sg2`, `opt`, `part.prf.act.msc.sg.gen` и т. д.

### Откуда данные

Источник — открытое зеркало словаря
[wirdeins.twanksta.org](https://wirdeins.twanksta.org/) (© Twānkstas Prūsa):
[github.com/strfry/wirdeins](https://github.com/strfry/wirdeins). Снимок NVH
от 22.11.2026 сохранён в `data/full.nvh`, список лемм — в `data/wordlist.json`.
Скрипты разбора и сборки:

```bash
# 1. разобрать NVH → JSONL
python3 scripts/parse_nvh.py data/full.nvh -o data/entries.jsonl

# 2. собрать CSV + SQLite
python3 scripts/build_data.py

# при желании обновить исходник из зеркала:
git clone --depth 1 https://github.com/strfry/wirdeins.git /tmp/wirdeins
cp /tmp/wirdeins/twanksta/nvh/full.nvh data/full.nvh
```

При сборке статьи-отсылки вида `↑ <лемма>` (это отдельно записанные формы без
перевода) наследуют перевод своей леммы — поэтому поиск по форме вроде
`galbimai` сразу показывает значение слова.

### Дополнения

`data/extra_entries.jsonl` — статьи, которых нет в зеркале NVH, но которые
нужны в словаре. `build_data.py` подмешивает их при сборке; если такая же
лемма позже появится в исходнике, дополнение пропускается (дубликата не будет).

Сейчас в файле три статьи:

- **ermērisnas** — отглагольное существительное женского рода (суффикс
  `-sna-`, парадигма 45) от `ermēritun` «придумать, выдумать» (корень
  `mēr-` «мерить, размерять, прикидывать» с приставкой `er-`). Значения:
  «выдумка, измышление», «оценка, расчёт», «мера, предписание».
  Формы: `ermērisnas` (sg.nom / pl.nom / sg.gen), `ermērisnan` (sg.acc /
  pl.gen), `ermērisnai` (sg.dat), `ermērisnamans` (pl.dat),
  `ermērisnans` (pl.acc).
- **saulīka** — «солнышко» (жен. род, парадигма 45; lt. *saulutė*,
  lv. *saulīte*, pl. *słoneczko*, de. *Sonnchen*, en. *little sun*).
  Фольклорная фиксация из Пиктупенена, песня «Mīniks saulīkan weddi»
  («Месяц на солнышке женился/-тся»). Формы: `saulīka`, `saulīkas`
  (sg.gen / pl.nom), `saulīkai`, `saulīkan`, `saulīkamans`, `saulīkans`.
- **teutōtisks** — «тевтонский; тевтонец» (прилагательное, парадигма 25,
  вариант `teutōtiskas`), из `[Ordo Teutonicus drv]`. Полная парадигма:
  24 положительные формы, 24 сравнительные, 24 превосходные и 3 наречия
  (всего 75), включая `ukateutōtiskais`. Переводы: ru, de, en
  (в источнике lt/lv/pl не заполнены).

### Ограничения

- 73 статьи без перевода — это служебные отсылки и несколько дефектных записей;
  они остаются в базе как формы, но без значения.
- Часть служебных слов в исходнике помечена как `noun` (например, местоимения
  `as`, `tū`); для `pn`/`ij`/`cj` в описании часть речи исправлена при сборке.
- Аналитические формы (перфект, футурум) не хранятся в NVH, а собираются в UI
  из причастий и фиксированных вспомогательных глаголов, как на оригинальном
  сайте.
- Данные отражают состояние зеркала на 22.11.2026 и не обновляются
  автоматически.

## Статический сайт (GitHub Pages, Cloudflare Pages)

Сервер не обязателен: `scripts/build_static.py` собирает папку `site/`, где
вся логика выполняется в браузере, а данные лежат одним JSON-файлом.

```bash
python3 scripts/build_static.py
cd site && python3 -m http.server 8080   # локальная проверка
```

| Файл | Размер |
|---|---|
| `site/data/dictionary.json` | 8,3 МБ (gzip ≈ 1,8 МБ) |
| `site/app.js` | 20 КБ |
| `site/index.html` | 28 КБ |
| **вся папка `site/`** | **≈ 8,4 МБ** |

Лимиты хостингов и запас:

| Хостинг | Лимит на файл | Наш самый большой файл |
|---|---|---|
| Cloudflare Pages | 25 MiB | 8,3 МБ (запас ≈ 3×) |
| GitHub Pages | 100 МБ (и ≈1 ГБ на сайт) | 8,3 МБ (запас ≈ 12×) |

CDN обоих хостингов отдаёт JSON с gzip/brotli, то есть реальная загрузка —
около 1,8 МБ. Индексация в браузере занимает ~1 с, память ~70 МБ.

**GitHub Pages:** собрать сразу в корень репозитория, чтобы не копировать
файлы вручную и не забыть `data/dictionary.json`:

```bash
python3 scripts/build_static.py --out /путь/к/репозиторию
```

затем *Settings → Pages → Deploy from a branch*, ветка `main`, папка `/ (root)`.
Пустой `.nojekyll` создаётся автоматически. Папку `site/` в репозиторий
класть не нужно — она только для локального предпросмотра.

**Cloudflare Pages:** подключить репозиторий с build command
`python3 scripts/build_static.py` и output directory `site`, либо загрузить
вручную: `npx wrangler pages deploy site`.

Интерфейс по-прежнему обращается к `/api/...`, но `web/localapi.js`
перехватывает `fetch` и отвечает из локального индекса. Поэтому один и тот же
`index.html` работает и с Python-сервером, и на статическом хостинге.

## API

Сервер отдаёт JSON (удобно для своих клиентов):

```
GET /api/search?q=kalba&lang=ru&limit=40
GET /api/suggest?q=kal&lang=ru
GET /api/entry?id=13
GET /api/gloss?text=As%20kalba&src=prs&dst=ru
GET /api/random
GET /api/stats
```

`lang`/`dst`: `ru`, `en`, `de`, `lt`, `lv`, `pl`.

## Структура

```
prussian/
├── server.py            # HTTP-сервер + JSON API (stdlib)
├── translate.py         # ядро: поиск, парадигмы, глоссирование, CLI
├── web/
│   ├── index.html       # интерфейс (один файл, без внешних ресурсов)
│   └── localapi.js      # клиентский API для статической версии
├── scripts/
│   ├── parse_nvh.py     # NVH → entries.jsonl
│   ├── build_data.py    # entries.jsonl → CSV + SQLite
│   └── build_static.py  # сборка статического site/ (GitHub/Cloudflare)
├── data/                # готовые данные + full.nvh + extra_entries.jsonl
├── site/                # результат build_static.py (готово к деплою)
└── start.sh             # запуск сервера
```
